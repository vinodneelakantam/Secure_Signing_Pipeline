Naming clarification
TF-A vs. TF-M vs. TIFS — not the same thing

          

            
TF-A (Trusted Firmware-A)
ARM's open-source reference firmware for Armv8-A application-class cores (BL1/BL2/BL31/BL32/BL33). Runs as BL31 on the Cortex-A72 cluster in this model — the EL3 secure monitor providing PSCI and SMC routing. Industry-standard, used across many vendors' SoCs, not TI-specific.

            
TF-M (Trusted Firmware-M)
ARM's separate, PSA-Certified open-source reference firmware for Armv8-M Cortex-M cores — a generic secure-partition runtime for constrained microcontrollers. It does not appear in this Jacinto-class boot chain; it's mentioned here only to avoid confusing it with TIFS below.

            
TIFS (TI Foundational Security)
TI's own, SoC-specific security firmware (the evolution of the K3 architecture's DMSC), modeled as the "Secure core (HSM role)" stage above. It plays a similar architectural role to what TF-M provides on other platforms, but TIFS is not built on or derived from TF-M — they are separate projects.

          

        

        
Reference model inspired by TI TDA4x-class (Jacinto 7) secure boot architecture. Stage names and roles illustrate the general industry pattern — ROM, secure core/HSM, SPL, bootloader, kernel — and are not a verbatim reproduction of proprietary implementation details.
